# 編集の確かめ用のデータ(#767・#774)

その場編集の残りの不具合を、手で確かめるためのファイルです。どれも Vellis で開いて、編集に入って試します。保存すると中身が変わるので、試したあとは `git checkout fixtures/edit/` で元に戻してください。

## #767 文書の末尾の改行がずれる

ソース編集(テキスト・Markdown のソース・HTML のソース)では、WebKit が文書の末尾の改行を「空の最後の行を見せるための仮の改行」として扱います。そのため、最後の行のあたりで打つと、末尾の改行が消えたり、1 つ増えたりします。途中の行の改行は正しく保存されます。

改行の中身は、ターミナルで `od -c <ファイル> | tail -3` と打つと見えます(`\n` が LF、`\r \n` が CRLF)。

| ファイル | 中身 | 試すこと | いまの結果 | 本来の結果 |
|---|---|---|---|---|
| `767-a-ends-with-newline.txt` | `abc\n` | `abc` の行末で Return → `x` → Command + S | `abc\nx`(末尾の改行が消える) | `abc\nx\n` |
| `767-b-no-final-newline.txt` | `abc`(末尾に改行なし) | `abc` の末尾で Return だけ → Command + S | `abc\n\n`(1 つ多い) | `abc\n` |
| `767-b-no-final-newline.txt` | `abc` | 末尾に `one` `two` の 2 行(最後に改行あり)を貼る → Command + S | `abcone\ntwo\n\n`(1 つ多い) | `abcone\ntwo\n` |
| `767-c-three-lines.txt` | 3 行・末尾に `\n` | `second line` の途中で Return → `x` → Command + S | 正しい(途中の行は崩れない) | 同じ |
| `767-c-three-lines.txt` | 3 行・末尾に `\n` | `third line` の行末で Return → `x` → Command + S | 末尾の改行が消える | `…third line\nx\n` |
| `767-d-crlf.txt` | 3 行・CRLF | `third line` の行末で Return → `x` → Command + S | 末尾の改行が消える(入れた改行は LF) | 末尾の改行が残る(CRLF にそろえるのは別の件) |
| `767-e-markdown.md` | Markdown・末尾に `\n` | Command + E でソース編集 → 最後の行の行末で Return → `x` → Command + S | 末尾の改行が消える | 末尾の改行が残る |

- 「いまの結果」は 2026-10-28 に WKWebView で確かめたもの(要件48 追補n の契約5・Issue #767)
- 最後の空の行(末尾の改行の後ろ)で文字を打つと `abc\nx` になるのは、ほかのエディタと同じ振る舞いで、不具合ではありません。不具合は、**行末で Return を押して**新しい行を作ったときに、元からあった末尾の改行が消えたり、1 つ増えたりすることです

## #774 HTML の編集面で、キャレットがダブルクリックした位置に来ない

HTML の文書の編集面(要件#53)は Shadow DOM の中にあります。ダブルクリックで段落の編集に入ると、キャレットはダブルクリックした位置ではなく、段落の先頭に置かれます。テキスト・Markdown・コードブロックでは、ダブルクリックした位置に置かれます(0.5.4 の要件48 追補p)。

ファイル: `774-html-edit-caret.html`

1. Vellis で開き、Command + E で編集面に入る
2. 段落の途中の単語(たとえば `P01` の段落の `w20`)をダブルクリックする
3. そのまま `X` を打つ

| | いまの結果 | 本来の結果 |
|---|---|---|
| `X` が入る位置 | 段落の先頭(`XP01 w01 …`) | ダブルクリックした所(`… w2X0 …` のように、`w20` の中) |
| スクロール | 動かない | 動かない |

単語には `w01`〜`w40` の番号を振ってあるので、`X` がどこに入ったかで、キャレットの位置が分かります。次の場所でも試せます。

- `P02`: 太字・斜体・リンク・コードの中の単語
- `H01`: 見出し
- `LI01`〜`LI03`: リストの項目
- `Q01`: 引用
- `TD01`・`TD02`: 表の中
- `P03`: div の中の段落
- `P04`〜`P15`: 下までスクロールしてから試す用の段落

試したあとは、Esc で編集を捨てる(Save を押さない)と、ファイルは変わりません。

- 機械での観察: 2026-10-29 の人間ゲートの機械確認(`tests/e2e/specs/req48nop-real-input-gate.e2e.ts` の p-4)で、本物のダブルクリックのあとの `X` が段落の先頭に入った
