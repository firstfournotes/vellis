# 在庫管理 API 仕様書 (テスト用ドラフト)

> このファイルは Vellis Phase 4.2 / 4.3 / 4.4 の動作確認用です。
> 実在のサービスとは関係ありません。AI に「修正してもらう」想定で
> 意図的に古い記述・ミスを 5 か所ほど混ぜてあります (検証手順は末尾)。

## 1. 概要

このドキュメントは在庫管理サービス `inv-svc` の REST API 仕様です。
v0.9 の仕様で記述されており、最新の v2 仕様には追従していません。
レビュー結果に基づき AI に書き直してもらう想定です。

## 2. 認証

### 2.1 アクセストークン

クライアントは Cookie ベースの認証を使用してください。
セッション ID を `inv_session` Cookie で送信し、サーバ側でセッション
ストアと照合します。

### 2.2 トークン更新

セッションは 30 分でタイムアウトします。タイムアウトする前に
`/auth/refresh` を呼ぶことで延長できます。

## 3. エンドポイント

### 3.1 在庫一覧の取得

```
GET /v1/items
```

レスポンス例:

```json
{
  "items": [
    { "id": "i_001", "name": "ねじ M3", "qty": 120 },
    { "id": "i_002", "name": "ナット M3", "qty": 80 }
  ],
  "total": 2
}
```

ページネーションは未対応です。1 リクエストで最大 100 件返ります。

### 3.2 在庫の追加

```
POST /v1/items
```

リクエストボディ:

```json
{
  "name": "ワッシャ M3",
  "qty": 50
}
```

`id` はサーバ側で `i_NNN` 形式の連番として割り当てられます。

### 3.3 在庫の更新

```
PUT /v1/items/{id}
```

`qty` のみ更新可能です。`name` の変更は別 API (削除→再作成) を
お使いください。

### 3.4 在庫の削除

```
DELETE /v1/items/{id}
```

物理削除されます。論理削除フラグはありません。

## 4. エラー応答

エラー時は HTTP ステータス 400 / 401 / 404 / 500 のいずれかを
返します。レスポンスボディは以下の形式です。

```json
{
  "error": "item not found",
  "code": 404
}
```

## 5. 制限事項

- 同時接続数: 50 まで
- リクエストボディサイズ: 1MB まで
- レスポンスタイム目標: P95 < 200ms
- 在庫数 (`qty`) の最大値: 9999

## レビュー観点 (Vellis での動作確認シナリオ)

以下のテキストを Viewer 内で範囲選択 → 「指示を追加」して
マークを作ると、Phase 4 の各機能を一通り検証できます。

### A. 認証セクション全体 (Phase 4.2 Moved 検証)

`§2.1` の段落 (Cookie ベース...) を選択 →
「OAuth2 Bearer に書き直して」と指示する想定。
AI 編集後 (Cookie → Bearer Token) に文字列がほぼ別物になるため
**Stale → 後続マークも別位置に Moved** が発生する。

### B. インライン精緻 (Phase B + 4.2 ChangedByAgent 検証)

`§5` の **`P95 < 200ms`** だけを選択 (インライン span)。
AI が `P99 < 300ms` に書き換えた場合、

- exact 一致は外れる
- fuzzy で 0.85 以上 → ChangedByAgent
- DiffView で span 範囲を確認

を検証できる。

### C. 表のセル (Phase 4.3 DiffView 検証)

`§6 既知の問題` の表セル `v2 で導入` を選択。
AI が表を再構成する想定。snapshot との before/after の差分を
DiffView で確認、必要なら「snapshot に戻す」で復元。

### D. heading 配下のロールアップ (Phase 4.2 heading_path 絞り込み検証)

`§3.1` 内の `id` という単語を選択。`id` は文書中に複数存在する
(JSON 例 / `§3.2` 〜 `§3.4` のパス) ため、heading_path
(`["3. エンドポイント", "3.1 在庫一覧の取得"]`) で絞り込まれる。

### E. CLI からの一括処理 (Phase 4.4)

`A` 〜 `D` のマークを 4 件作って **inbox 生成** したあと、
ターミナルで:

```bash
# 動作確認 (cat で inbox の中身を確認するだけ)
vellis --fix echo

# 実際に AI を呼ぶ場合 (要 ~/.config/vellis/agents.toml + claude CLI)
vellis --fix claude
```

`vellis --fix echo` が `agent-inbox.md` の内容を表示し
exit code 0 で抜ければ Phase 4.4 経路は OK。
